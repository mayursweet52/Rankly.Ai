Mechanical Component Breakdown

1. The Frontend UI Shell (Sumit)

  • DOM Views: The 11 core public HTML files built on a strict neo-minimalist Tailwind system.
  • Theme Engine (uiPolishSuite.js): Injects dynamic behavior, overriding standard OS inputs and applying WCAG AAA focus rings.
  • Feature Scripts (upload.js, hrCandidateQueue.js): Handle drag-and-drop resume ingestion, scorecard rendering, and real-time candidate list population.

2. The Gateway & Middleware Layer (Mayur)

  • Security Checkpoint: Before any data reaches the backend, requests pass through express-rate-limit (DDoS protection).
  • JWT & Session Verification (auth.js): Intercepts requests, validates Bearer tokens or cookies, and enforces Role-Based Access Control.

3. The Core Backend Mechanics (Mayur)

  • Controllers & Routing: Map frontend requests to internal actions. The healthController.js acts as a diagnostic hub, while userController.js processes HR logic.
  • Self-Healing Daemon (healthChecker.js): Runs continuously in the background, verifying system integrity, checking database connections, and catching anomalies without human intervention.
  • Export Engine: Uses ExcelJS to serialize candidate queues into downloadable CSV/Excel formats for external HR processing.

4. The AI Processing Pipeline (Mayur)

  • Ingestion: documentParser.js mechanically strips formatting from uploaded resumes, extracting raw semantic text.
  • Evaluation: aiMatcher.js packages the parsed text and job requirements, streaming them out to the NVIDIA Nemotron AI engine. It then structures the AI's response into numerical scorecards for the frontend.

5. The Data Infrastructure (Vaibhav)

  • Prisma ORM: The absolute source of truth mapping JavaScript objects strictly to the SQL database schema (prisma/schema.prisma).
  • Supabase Realtime Workers: Listen for database mutations (like a new candidate applying) and push live WebSocket updates directly back to the hrCandidateQueue.js on the frontend, ensuring the recruiter dashboard never needs to refresh.
